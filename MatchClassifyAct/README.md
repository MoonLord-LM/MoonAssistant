# MatchClassifyAct（MCA）

> **Match the pixels, Classify the state, Act accordingly.**
> 匹配像素 → 分类标注 → 执行动作。

Spring Boot 3.2.5 + JDK 17 + JNA 的 Windows **图形程序自动化**工程：对任意 GUI 窗口做「后台截图 → 人工给画面状态打标 → 实时识别当前画面属于哪个状态 → 按定义发送鼠标点击」。默认演示目标是 MuMu 模拟器内的安卓程序，改配置即可自动化任意窗口。

```
截图（窗口内容） → 分类标注（人工，控制台） → 对照图产物（汇总分析）
                                              ↓
                            执行模式：实时画面比对识别 → 鼠标点击
```

---

## 一、快速开始

前置：JDK 17 + Maven；须在**真实桌面会话**运行（无桌面环境抓不到窗口）。

```powershell
mvn -DskipTests package
java -Dfile.encoding=UTF-8 -jar target/MatchClassifyAct-0.0.1-SNAPSHOT.jar
```

- 启动就绪后自动以 Edge/Chrome 应用窗口打开控制台（`http://localhost:8080/annotate`，`--ui.auto-open=false` 可关）；页面会持续探测后端，检测到代码更新后**自动刷新**加载新版。
- 自动采集（截图）**默认不开启**，需在页面右上角点「自动采集」；右上角「完全退出」结束服务并自动关页。
- 日常重启用 `restart.cmd`（停旧进程 → 清 `target\` → 重新打包 → 启动，日志在 `log\`）；`stop&clean.cmd` 只停并清构建输出。
- 数据都在运行目录下，启动自动创建；**可随时整目录拷贝/备份**。

## 二、目录与数据流

| 目录 | 内容 |
|------|------|
| `capture/` | 后台采集的**原始截图**（未标注，`IMG_yyyyMMdd_HHmmss_SSS.png`） |
| `classify/` | 保存标注时图从 capture/ 移入；图旁同名 json **只记归属** `{"state":…}`；`data.json` = **分类定义中心表**（每分类一份动作+坐标） |
| `summary/<分类标注>/` | **汇总分析产物**：对照图（15 张基础合成图 = 交集六档 same100/90/80/70/60/50（100% = 样本像素完全一致，其余覆盖 >90%/80%/70%/60%/50%）与多数/均值/去重均值/8·32 块图族；每张基础图各带 1 张 `-unique` 独有区图，共 15 张——基础图与独有区图**全部参与识别比对**；每个分类以**注意点**（未设 = 屏幕中心）为中心另含 12 张**注意区交集图** = 1/8、1/32 方框 × 交集六档，鼠标点击分类再以**点击点**为中心另有 12 张**点击区交集图**，同样全部参与比对）+ `info.json`，仅供人工目检 / 执行识别，可随时整目录删除后重算 |
| `summary/_all_/` | 汇总分析列表**固定第一条「全部」**的产物：**12 张** = 交集图 6 张（`same100.png` 100% 档 = classify/ 全部已标注截图的**公共部分**、`same90/80/70/60/50.png` = 每像素取一致张数 >90/80/70/60/50% 的**稳定区**）+ 多数 / 均值 / 去重均值 3 张代表图（`major.png` 多数图、`avg.png` 均值图、`dedup-avg.png` 去重均值图）+ 这 3 族「**与代表图差异最大的一张原图**」（`<kind>-maxdiff.png`，直接复制命中的原图 PNG，不重编码）+ `info.json`（`items` 记 12 张的角标与命中原图名：交集族角标 = 覆盖像素占比，其余族代表图 = 全部原图与该图的平均差异）；不做分类分组、不参与识别比对，仅供整体目检（分类标注若与「全部」同名，目录名自动加 `_cls` 后缀，两者互不影响） |
| `classify/dedup-cache.json` | 启动历史重复清理的**比对结果缓存**（在 `classify/` 里与已标注截图同目录，可随时删除，删了只是下次多算一遍；旧版放在运行目录根下的同名文件首次访问时自动搬入）：JSON 记录「互相比较过的文件组」，形如 `{"version": 1, "pairs": { "IMG_a.png@<mtime>": { "IMG_b.png@<mtime>": 不一致像素点占比 } }}`——每对图只记一条（两侧身份按字典序、小的作外层键），所以**每个文件组独占一行**、可直接查看与裁剪；四元组都没变过的组合下次启动**直接复用、不再逐像素比对**，已删除文件的条目在下次清理时自动裁掉 |
| `summary/opt-result.json` | 「算法调优」结果的**完整缓存**（可随时删除，删了回到「未计算」；随 `*.json` 一并被 git 忽略）：形如 `{"version":1,"fp":"<验证指纹>","sig":"<算法结构签名>","savedMs":…,"samples":…,"groups":…,"result":{…各算法结果 + 逐分类明细…},"tune":{…最近一次自动调整参数摘要…}}`——进程启动首次访问算法调优（或 `tunable()`）时若文件在、且 `fp`（已标注 + 汇总分析没变）与 `sig`（算法组合口径没变、特征验证结果都还新鲜）都对得上，就直接恢复上次结果与调整摘要（界面显示上次结果，无需重算）；对不上即标记为「已过期」并提示重新计算。写盘同样先写 `.tmp` 再原子改名 |
| `summary/verify-matrix.json` | 「特征验证 / 算法调优」共用的**逐图比对结果缓存**（可随时删除，删了只是重算一遍；随 `*.json` 一并被 git 忽略）：形如 `{"version":1,"fp":…,"savedMs":…,"kinds":{"same90":{"cols":[[state,w,h,attnLeft,attnTop,actLeft,actTop,产物mtime,产物size,info.json mtime,info.json size],…],"decoded":[…],"valid":[…],"rows":{"img_0001.png":[mtime,size,w,h,[与各分类的不匹配占比…]],…}},…}}`——两层键：**列**（该特征在每个分类目录下的产物与 `info.json` 的大小 + 修改时间，外加尺寸 / 注意点 / 点击点）对得上就说明产物像素与裁剪框心没变、**整表照用**（连「该分类有没有有效产物」也照用，一个 PNG 都不解码）；**行**（原图文件名 + 大小 + 修改时间 + 所属分类宽高）对得上就**直接取用该行分值**（连原图都不解码），只有真正变过的那部分重算。分值按双精度原样写盘（可无损读回，保证「并列」判定与重算完全一致）；比对口径（`compareKind` / 裁剪）改了要 bump 文件里的 `version`，否则旧数值会被当成新口径复用。特征验证一次完整跑完（无中断）后与 `verify.json` 一起落盘（先写 `.tmp` 再原子改名）；算法调优 `prepare()` 的矩阵读的是同一份、特征验证刚跑完就直接在内存里命中 |
| `summary/opt-weights.json` | 「算法调优」的**特征选择 + 权重数值快照**（每次「验证所有算法 / 自动调整参数」跑完覆写一份最新的，可随时删除）：形如 `{"version":1,"fp":…,"sig":…,"algos":[{"id":…,"name":…,"tunable":…,"features":[{"kind":…,"x":…,"a":…,"b":…,"c":…,"e":…,"other":…,"why":…}],"weights":[…],"accuracy":…,"tieRate":…}]}`——`features[].kind`（特征选择）与 `weights`（权重 Y，0~2、精度 **0.001**）**一一对应**，含当时指标，供后续功能（例如执行模式）与开发验证直接读取，不必解析界面状态；它与上面 `classify/opt-weights.json`（界面可调 Y 的持久化，单一特征算法不写）是两份不同用途的文件 |
| `classify/opt-weights.json` | 「算法调优 → 自动调整参数」落盘的**当前生效权重**（同样在 `classify/` 里，可随时删除、删了回到默认全 1）：形如 `{"version": 1, "algos": { "<算法id>": { "kinds": ["same100", …], "y": [0.37, 1, …] } }}`——`kinds` 记特征顺序、与 `y` 一一对应（特征集合变了这条自动作废、按全 1 处理）；`y` 为 0~2 的权重、**精度 0.001**（手写更多位数读出时按 0.001 收齐）；界面上的权重输入框以这份文件为起点（改完文件刷新页面即生效），点「自动调整参数」时每采纳一处调整就原子重写一次（先写 `.tmp` 再改名）。单一特征算法不写进文件（权重恒为 1） |

数据布局例子：

```json
// classify/data.json   —— 分类级统一定义（动作 / 点击点 / 注意点只存这里）
// click 分类：left/top = 点击点（执行时真正点击、必填）；attnLeft/attnTop = 注意点（可选，不写或写 null = 默认屏幕中心）
{ "登录页": { "action": "click", "left": 640, "top": 360, "attnLeft": 500, "attnTop": 300 } }
// 无动作分类：没有点击点，只有注意点（可选，不写或写 null = 默认屏幕中心）
{ "等待中": { "action": "none", "attnLeft": 640, "attnTop": 360 } }
// classify/IMG_xxx.json —— 每张样本只写归属
{ "state": "登录页" }
```

旧版单目录 `captures/`（截图/标注/汇总混排）若存在，启动时自动迁移到上述三分区，之后不再读写。

## 三、控制台使用

左上角「工作模式」下拉在 **标注模式 / 执行模式** 间切换。

### 3.1 标注模式（打样本）

顶栏六段导航：**全部 / 未标注 / 已标注 / 汇总分析 / 特征验证 / 算法调优**。流程：看图 → 填分类标注 → 定匹配动作与点 → 保存并下一张。

- **分类标注** = 画面状态名（登录页 / 主界面 / 弹窗…）。它同时用作汇总产物目录名，故不能含 `\ / : * ? " < > |` 等文件名非法符号（输入时自动剔除）。chip 上的 ✎ 可整体改名（中心表 key 与全部样本归属一并更新，旧产物目录自动清理）。
- **匹配动作** = 无动作 / 鼠标点击，每类各带 **2 个点（双点，编辑面板分三行：分类标注 / 动作 / 点击点·注意点·清除注意点）**：
  - **点击点**（红点）= 执行模式真正点击的位置，仅「鼠标点击」分类有、必填；也是**点击区交集图**的框心。
  - **注意点**（绿点）= **注意区交集图**与识别裁剪的中心，任何分类都可设置；**未设 = 默认屏幕中心**（所有分类一致，不再回退点击点），鼠标点击分类的注意点可与点击点分别设置。
  - 图上用 `点击点 / 注意点` 切换按钮选择当前编辑哪个点，再在图上点一下即可落入该点；只切换编辑目标不算修改，点「清除注意点」才标记为修改（清除后该分类的注意点恢复默认屏幕中心）。
- 每个分类只有一份定义：**首次**打标时确定，之后同分类加样本直接填分类保存即可，坐标自动沿用；在已标注图上改动作 / 点击点 / 注意点 = **重定义该分类**（全组同步，保存前会提示旧定义与新定义的差异）。唯一动作只约束**仍在使用（有样本）**的分类；样本删光后中心表残留的空定义视为全新分类，下次首标会直接重新定义，不会挡你新建。
- 保存后自动带出上次标记并跳到未标注图，快捷键 `↑`/`↓` 切图、`Enter` 保存，可连续快速打标。
- 「已标注」视图里点标签右侧的数字 = 只浏览该分类的已标注图并跳到第一张（再次点击同一数字取消过滤），不会跳去「全部」。
- 左侧列表排序：全部、已标注按时间倒序（最新在上）；未标注按时间正序（最旧在上），从最早的开始逐张往下打标。
- **图片像素 = 窗口坐标**（截图即窗口内容，resize 已逐像素对齐），坐标语义一直沿用到执行点击。

### 3.2 后台截图与去重

- 页面点「自动采集」后按 `capture.interval-ms`（默认 1s）周期后台截图，节拍是 **fixedDelay**：处理完一帧再等这么久取下一帧，绝不叠帧。
- 每帧保存前与历史全部 PNG（capture/ + classify/）全尺寸逐像素比对、统计不一致像素点占比，须与每一张都 > `capture.diff-threshold-percent`（默认 5%）才保存，否则判为重复丢弃；结果以单条轻提示展示在右下角（保存成功 / 与哪张重复）。
- **每次启动**还会在后台自动清理一遍历史重复（自动截图与手动去重任一开启即执行）：按两个启用阈值中较低者（默认 min(5, 0.5) = 0.5%）逐像素比对，只删与保留图不一致像素占比 ≤ 阈值、几乎重复的截图（近似但不相同的画面一律保留），避免误删；画面持续变化产生的新重复仍靠运行期去重挡。清理结果（无论有无删除）在右下角提示一次、并完整进「历史日志」：含参与张数、删除张数、**实际全尺寸比对次数**、**其中复用缓存省掉的次数**与**最低的不一致像素占比**（= 最接近重复的一对还差多少，未删除时据此判断离阈值有多远；无可比对的同尺寸图时省略该段）与耗时。
- 每次的比对结果都按**两张图的文件名 + 最后修改时间**四元组持久缓存在 `classify/dedup-cache.json`（与已标注截图同目录，JSON「互相比较过的文件组」）：四元组都没变过的组合下次启动**直接复用、不再逐像素重算**（所以全量重扫过一遍后，重启几乎瞬时完成、连 PNG 都不必再解码）；缓存的是**差异值**而不是「是否重复」，判定仍拿本次阈值去比，改阈值 / 文件内容变了（mtime 变 → 该条自动失效）都不会用错或漏算；缓存条目按本次枚举到的截图集合裁剪（已删除文件的条目丢掉），不会随历史无限增长，文件本身也可随时删除。
- 这次清理**开始 / 进行中 / 结束各有一条消息**（历史全量逐像素比对可能持续较久，避免看起来像卡住）：开始时右下角提示一条「启动重复清理：开始检查…（口径 + 文件名/修改时间没变过的组合直接复用上次结果）」；进行中显示一条**一直刷新**的进度消息——「正在检查重复图片：已判定/待判定 张数（当前文件名）（已耗时 N 秒 · 已比对 N 次 · 复用 N 次）」，已耗时**逐秒走动**（后端逐张写进行态快照、`GET /api/app/meta` 的 `startupDedup` 下发，页面每 2 秒取一份 + 本地 1 秒 ticker 复现；进度只显示不入「历史日志」，避免每张一条刷屏）；结束后进度消息撤掉、由上面那条结果提示收尾。这条进行态文案由前端 `progLine()` 统一模板生成，控制台里所有「长任务进行中」提示（汇总分析的清场 / 统计待分析组合 / 生成对照图 / 排队，见 3.3）都用同一套写法，便于一眼比对。
- 截图目标尺寸不符 `capture.resize-width × resize-height`（默认 1280×720）时，自动用 `SetWindowPos` 缩放窗口后重截验证，直到 PNG 恰好达标才保存。

### 3.3 汇总分析（生成对照图）

进入「汇总分析」段会自动异步分析每个「样本 ≥1 张且尚未分析」的分组；样本有变也会自动标记待重算。列表**固定第一条「全部」**（不是分类标注、不参与动作过滤与识别比对）= 把 classify/ 全部已标注截图合成**12 张专用产物**：交集图 6 张（100% 档 = **所有图片的公共部分**，只有每一张都完全一致的位置才保留真实颜色、画面里恒定的边框/标题栏之类会浮现出来；90/80/70/60/50% 档 = 每像素取一致张数 >90/80/70/60/50% 的颜色 = **样本间稳定区**）+ 多数 / 均值 / 去重均值 3 张代表图（与该组原图**同尺寸且全不透明**，与分类产物的同名 kind 算法完全一致）+ 这 3 族「**与代表图差异最大的一张原图**」（把全部原图逐个与该族代表图逐像素比对，低 24 位不同的占比最高者胜出，直接复制该原图 PNG 落盘、不重编码）；样本有变时与其它分组同一轮后台重算。产物 = **对照图**（15 张基础合成图 = 交集图分六档：100% 档 = 全部样本像素一致（最严格），其余按覆盖率阈值 >90%/80%/70%/60%/50% 分档，再加多数/均值/去重均值/8·32 块图族；每张基础图各带 1 张对应的 `-unique` 独有区图，共 15 张；每个分类以**注意点**（未设 = 屏幕中心）为中心另有 12 张**注意区交集图** = 1/8、1/32 方框 × 交集六档；鼠标点击分类再以**点击点**为中心另有 12 张**点击区交集图**）+ `info.json`（样本数 / 覆盖率 / 注意点与点击点坐标等），**供人工目检，并作为执行模式实时识别 / 智能分析建议的比对源——只读使用，不自动改动任何标注**（基础图、独有区图、注意区与点击区交集图全部参与识别：每个分类 15 + 15 + 12 = 42 张，鼠标点击分类 15 + 15 + 12 + 12 = 54 张；历史旧产物只有 30/42 张，后台重算后补齐）：

| 产物 | 含义 |
|------|------|
| `same100.png` 交集图（100% 档 = 全部样本一致） | 每像素统计全部样本颜色，仅当**每一张**样本在该像素都同色（一致张数 == 样本数）才保留该真实像素色，任何一张有差别的像素一律透明——交集档里最严格的公共区，只留下所有截图完全恒定的画面；参与识别比对与独有区互比 |
| `same90.png` 交集图（90% 覆盖率档） | 每像素统计样本中主流颜色及其出现占比，覆盖率 >90%（一致张数需超过样本数 × 90%）则取该主流色、不足则透明 = 样本间公共（稳定）区；参与识别比对与独有区互比 |
| `same80.png` / `same70.png` / `same60.png` / `same50.png` 交集图 | 合成方式同上、仅把达标阈值放宽到 >80% / >70% / >60% / >50% 的公共画面，低门槛档保留更多稳定区、与 90% 档互补。**同样参与识别比对**；每档各带 1 张参与比对的 `-unique` 独有区图 |
| `major.png` 多数图 / `avg.png` 均值图 / `dedup-avg.png` 去重均值图 | 每像素取出现最多的颜色 / 全部样本 RGB 平均 / 对样本在该点出现过的颜色**去重后再逐通道等权平均**（同画面重复截再多也只按一个颜色计，抽样不均不再把平均拉偏） |

### 3.4 特征验证（第 5 视图，挑特征）

左栏列出**全部 kind**（顺序 = `FrameClassifier.verifyOrder()`，不另写清单），每行 = 状态 chip + **只给两个数：D 匹配正确率 · E 无法区分率**（A/B/C 与样本数只在主图区的汇总卡与明细表里）；主图区给出**五个**指标的汇总卡与逐分类明细表（分类 / 匹配动作 / 自分类平均 / 是否生成成功 / 匹配正确率 / 匹配正确分类的个数 / 无法区分率 / 无法区分的个数）；右栏是说明 + 「开始验证」+ 进度。左栏过滤按钮固定两个：`生成成功率100%`（A ≥ 100）与 `匹配正确率80+%`（D ≥ 80）。

- **A 生成成功率** = 能生成有效合成图（产物存在且非全透明空图）的分类数 / 参与分类数：越高说明该算法适用的分类越多。
- **B 自分类平均匹配值** = 有效分类样本「与自家产物」匹配像素占比（= 100 − 不匹配占比）的平均值：越高说明该特征对本分类越稳定。
- **C 其它分类平均匹配值** = 有效分类样本「与其它分类产物」匹配像素占比的平均值：**越低越好**，越低说明越能把它与别的分类分开。
- **D 匹配正确率** = 在能生成有效图的分类里，原图与「所有分类的该算法生成图」比对、最佳命中**唯一最高**且**恰好是自己分类**的占比；**无法生成有效图的不参与统计，无法给出最高值的结果（最高分被 ≥2 个分类并列、分值一样、分不出该选哪一类）的也不参与统计**（这些样本只计入 E）→ 分母 = 可匹配样本数 − 无法区分数（= 命中 + 误判）。D 卡副标题写「（可匹配样本 N 张，其中能给出结果 K 张）」。D 告警色：低于 50 红、低于 90 黄。
- **E 无法区分率** = **全部可匹配样本**里，**无法给出最高值的结果**（最佳命中被 **≥2 个分类并列**、分不出该选哪一类）的占比（越低越好）。分母 = 全部可匹配样本（命中 + 无法区分 + 误判 = 可匹配样本数）——**与 D 的分母不同**，故 D + E 不一定等于 100%。E 告警色：≥50 红、≥20 黄。分类行的「查看详细」按钮**分列给出、各看各的**：**D 列（匹配正确率）**的按钮只列**匹配错误**样本（最佳命中唯一但不是自家，按被误判到的分类分组、条数多的组在前，每行「命中 x% · 自家 y%」＝ 与误判分类生成图／与自家生成图的匹配占比），**E 列（无法区分率）**的按钮只列**无法区分**样本（最高分被 ≥2 个分类并列，每行「并列 A、B · 最高 x% · 自家 y%」）；本列没有对应样本就不出现该按钮（另一列仍可单独打开），也**不再要求 D < 100%**——D 的分母已排除无法区分样本，可能出现「D = 100% 但仍有无法区分样本」。两个弹窗是**同一套版式**（同一个 `#vkDetailModal` 容器 + 同一组 `.xcard` / `.xmeta` / `.list` 样式，只有标题与说明段不同），且都**覆盖整页**（看不到身后的右栏与表格），故标题写明主体、标题下再用一行信息 chip 交代上下文：标题 = `匹配错误明细` / `无法区分明细` ` - <分类标注> ｜ <匹配动作>`，chip = `汇总图算法 <短名>`、`样本 N 张`、`匹配正确率 x%`（按 D 告警色）、`匹配正确个数 h / 能给出结果 k`、`匹配错误 w 张`、`无法区分率 y%`（按 E 告警色）、`无法区分个数 t / 可匹配样本 N`；下方说明段讲清本段各行的读法，单击缩略图看原图大图。执行模式的「详细分值」弹层同规：标题 `对照图分值 - <分类>`，chip = `本帧差异度 x%`、`对照图来源 <matchedFile>`，两处共用 `.xmeta` 样式。
- **不能生成有效产物的分类及其样本不进任何指标统计**：某分类没有该 kind 产物、或产物为全透明空图（缺注意区/点击区交集图、独有区图无独有点等）＝无判别点；明细行对应数值显示「——」，A 在产物无效时后端直接给 null。
- **覆盖范围统一**：每种 kind 都拿全部原图 × 全部分类比对，不按动作收窄。
- **结果完整缓存到 `summary/verify.json`**（2026-09-12）：一次验证完整跑完（无中断）即把全部 kind 的结果**完整落盘** —— 五种指标 + 全部逐分类明细行 + 「查看详细」用的逐图明细（匹配错误 / 无法区分）一并写入（先写 `.tmp` 再原子改名，中途被杀只丢本次；文件可手删，随 `*.json` 一并被 git 忽略）。进程启动后首次访问本视图（或算法调优 `statOf()` 取值）时若文件存在就**完整恢复上次结果**，于是「**已标注（`classify/` = 原图 + 标注 json + `data.json` 分类定义）与汇总分析（`summary/` 全部产物与 `info.json`）的数据一个字都没变（指纹一致）」时界面直接显示「已计算」，**不必重算** —— 右栏统计行会多一行「已从 summary/verify.json 恢复上次结果（数据没变即可直接用）」，明细页的完成时间 / 耗时 / 五张指标卡 / 明细表 / 「查看详细」弹窗全部照旧可用。反过来，只要这两处**有任何变动**（增删改原图 / 标注 / 分类定义，或产物 png 与 `info.json` 变化），指纹随之改变 → 恢复出来的结果立即标记为**过期**：左栏 chip 变琥珀「需重算」、右栏统计行追加「注意：已标注 / 汇总分析的数据有变动，需重新验证（N 种）」、并**弹一次提示**（按指纹去重，同一份变动只提示一次，数据重新一致后再变动会再提示）、明细页状态 chip 显示「已过期 · 需重算」；点「开始验证」重算即覆盖缓存。**另外每个 kind 逐图比对的原始分值（`[样本][分类]` 不匹配占比矩阵）单独缓存到 `summary/verify-matrix.json`**（2026-09-12，见数据表那一行）：按「原图 / 产物各自的大小 + 修改时间」记账，没变过的整表 / 整行直接复用（连 PNG 都不解码），所以即使指纹变了、必须重算，也只会重算真正变过的那部分（例如刚重算过某个分类的产物，只会作废受影响的那些表）；右栏统计行会多一行「逐图比对结果缓存：summary/verify-matrix.json（已载入 N 种特征 · M 条样本行）」，验证跑完后再补一行「其中直接复用逐图比对结果：N 条样本行 · M 种特征（没变过的图不重比）」。**「算法调优」用的就是同一份矩阵**，故「特征验证 → 算法调优 → 自动调整参数」连跑时一次都不必重复比对。
- 指纹在统计 `classify/` 与 `summary/` 全部文件（名称 + 大小 + 修改时间 → hashCode，3 秒 TTL）时**排除 `verify.json` / `verify-matrix.json` / `opt-result.json` / `opt-weights.json` / `dedup-cache.json` 这些非产物数据文件**（连写盘用的 `*.tmp` 临时名一起排除）—— 否则「写缓存 / 保存权重」这一步会反过来把自己判成过期（自动调整参数一落盘，验证结果就全变「需重算」）。
- 验证任务在后台单线程 + 并行流跑，页面停留该视图时 1 秒轮询进度。验证期间常驻缓存回收交给 JVM 的 GC（无任何手动清理入口），但两者都会长时间占用 CPU 与磁盘 IO，因此**不建议与执行模式的自动识别并行**。
- **顶栏（`.stagebar`）只写视图名「特征验证」**：进视图时由 `setStageTitle()` 显式重置（`#fname` = 视图名、`#fsub` / `#imgDims` 留空），否则会残留上一个视图（如汇总分析）的「分类 ｜ 动作 / 原始截图 N，分析产出 M」；样本库 / 已算口径统一由右栏 `#vkStat` 承担（该行 `white-space:pre-line`，恢复提示 / 需重算提示各占一行）。

### 3.5 算法调优（第 6 视图，组合特征成匹配算法）

建立在第 5 视图「特征验证」的结果之上：用 A/B/C/D 自动挑特征（E 只做展示、不参与挑特征）、组合成「匹配算法」，再逐张原图验证每个算法的分类匹配正确率。**前置条件**：先在「特征验证」跑完一次且样本 / 产物未变动（指纹一致），否则主图区提示先去完成特征验证。注意 D 的口径（2026-09-12 起）：分母只算「能给出结果」的可匹配样本（不含无法区分），所以 `D = 100%` 的含义是**没错判**、允许存在无法区分样本；本视图算法 2/3/4/5 的种子档位（D = 100% / D ≥ 90% / D ≥ 80% / D ≥ 70%）都跟着这个新口径走。本视图自己报告的「匹配正确率」同样在分母里剔除无法区分样本（2026-09-12 第三次修正：`命中 / (可判定样本 − 无法区分)`，无法区分不再算作判错），**与 D 的分母完全一致、数值可直接对比**；无法区分率 = `无法区分 / 可判定样本`，与 E 同口径（故两者之和不一定等于 100%）。

- **内置五种算法**（特征集合由验证结果自动组合，卡片里列出每个特征的入选依据；算法 1 的选品口径 = **(生成成功率 A − 无法区分率 E) × 匹配正确率 D 最大**，后四个都把这个「单一最佳」特征作为种子之一带上）：
  1. **单一最佳匹配特征** = 取「(A − E) × D」最大的一个特征，只用它判定（不再限制 A = 100%，A 与 E 已经在式子里面）；

- **进度精确到张**（2026-09-12）：阶段一每个特征、阶段二每个算法都要跑全部张样本，「外层项数」会长时间不跳（一张矩阵几分钟），所以后端 `Run` 增加了张数字段 `processed / totalSamples / sample`（当前项内已比对到第几张 + 最近一张文件名）与跨阶段合计 `allDone / allTotal`，`buildMatrix()` 的并行流用 `AtomicInteger` 逐张回报、`evalAlgo()` 逐样本回报，`status()` 再下发 `elapsedMs`（运行中已耗时）。右栏第一行 = 「阶段：逐特征比对矩阵　3/6 个特征（交集图 100%）　第 128/807 张」，第二行 = 「正在比对 img_0123.png · 已耗时 42 秒」；**进度条按跨阶段合计张数连续推进**（不再随阶段切换回零、也不等整张矩阵跑完才跳一格），拿不到张数时才退回外层项占比。stats 行同步带上「· 第 N/M 张」。
- **打平口径 = 与特征验证的「匹配正确率 D / 无法区分率 E」完全对齐**（2026-09-12 二次修正，取代「并列算命中」的旧口径）：① `evalAlgo()` 先逐样本**逐特征**剔掉「分不开」的特征——某特征的最高匹配值被 **≥2 个分类并列**（分值一样、分不出该选哪一类）即视为该特征有问题，这张样本的加权平均里**整张放弃该特征**（对该样本全部分类一致移除，只改一半会变成两套口径）；② 再用剩余特征重新加权，匹配度**唯一最高**才算判定结果，**仍并列**（或本样本可用特征被全部放弃 / 归属分类无从判定 → `bestScore` 或 `ownScore` 为 `-inf`）一律给「**无法区分**」结论，既不算命中也不算判错，单独计入 `tie`（`tieRate = tie / samples`，界面「无法区分率」）；③ 归属分类在本算法参与特征上**没有可判定的产物**（`VerifyService.hasPixels` 口径：产物存在且至少一个不透明像素；比对结果 `-1` 视为比不了）的样本整张**跳过**（`skipped`）、不计入分母，与 E 的「可匹配样本数 `cSamples`」一致（D 的分母另要再排除「无法区分」的样本）。于是当「单一最佳」选到的正是 `same100` 时，同一份数据下它的正确率与特征验证的 D 完全对得上：847 张可判定样本里 628 张命中、219 张无法区分、0 张判错 → 正确率 **100%**（628 /（847 − 219））、无法区分率 25.86%（219 / 847）。（2026-09-12 第三次修正前，本视图把无法区分算作判错、按 `628 / 847` 报 74.14%，与验证的 D = 100% 自相矛盾；改成同口径后两边一致。）`buildMatrix()` 返回 `Matrix(不匹配占比矩阵, 各分类该特征是否有效产物)`，`evalAlgo()` 用它算可匹配样本与并列判定。
- **自动调整参数**（2026-09-12，`POST /api/optimize/auto`）：右侧「验证所有算法」旁边的次按钮，**必须先在「验证所有算法」跑完一次、且结果与当前样本 / 产物一致**（后端 `tunable()`：不在跑任务 + 验证已完成 + 指纹没过期）才能点，否则按钮禁用（悬停提示原因）。它复用同一套比对矩阵——同一份 `AlgoEval`（与权重无关的预计算：矩阵引用 + 每张样本各特征「分不开」的标记只算一次），换一组权重只跑加权评分，所以能对同一算法评估上百上千次。逐个可调权重把 Y 分成**两轮、每轮各试 100 次**（`TUNE_TRIALS = 100`，共 `TUNE_ROUNDS = 2` 轮；试探总次数 = 可调权重数 × 2 × 100，5 个特征的算法即 1000 次评分），每次都重算该算法的匹配正确率与无法区分率：**第一轮整段随机**（0~2 之间的随机值）、**第二轮就近微调**（在第一轮定下来的值附近按 **±0.001 ~ ±0.1** 随机取一档加上去，`TUNE_FINE_STEPS = 100` 档步长、再夹到 0~2 并按 0.001 收齐）；所有取值都精确到 0.001（`Y_SCALE=1000`）。**只要这次改动让匹配正确率上升、或无法区分率下降就采纳**（每轮内部在 100 个候选里取「正确率更高、再比无法区分率更低」的那个当新值；某一轮 100 次都没能改善就保持**本轮起点**、不动，第二轮的起点即第一轮采纳后的值）。**某个权重的这一遍（= 随机 + 微调两轮）里采纳过更好的值，就从这个新值再整段来一遍**（`TUNE_REPEAT = 3`，最多追加 3 遍、单个权重最多跑 1 + 3 遍；进度行显示「第 N 遍」，追加的遍数也计入合计张数、进度条不会提前走满）——随机与就近微调接力，避免只试一遍就停在局部最优。每采纳一次就立刻把该算法当前的全部权重**原子写入** `classify/opt-weights.json`（先写 `.tmp` 再 `REPLACE_EXISTING` 改名，中途被杀只丢最后这一次调整），全部算法调完再用**最终权重**重算一遍全部算法并把结果写进 `result`。于是：`status()` 的 `algos[].weights` 就是「当前生效权重」（= 权重文件里保存的那份；单一特征算法恒 1、不写文件），前端拿它对签名，变了就同步到权重输入框、结果卡与结论（并在非首次同步时提示「已应用后端保存的权重 Y」）；权重文件按 mtime 缓存解析结果，**手改文件刷新即生效**（手输与文件里的 Y 都按 **0.001 精度**收齐：0~2 之间、超出三位小数四舍五入到 0.001），删了回到默认全 1（特征集合与文件里记的 `kinds` 对不上时该条作废、按全 1 处理）。单一特征算法**不参与调整**：只有一个特征时 Y 在 `Σ「X × Y」` 里被约掉，随机改它对加权平均没有任何影响。进度同样按张数推进，右栏额外显示「当前是哪个算法 · 哪个特征 · 第几遍 · 哪一轮（随机 / 微调）第几次尝试（试到的 Y）· 该权重的基线正确率 / 无法区分率 · 已找到的最好结果」；跑完不再单独占一张结果卡（2026-09-12 去掉）：采纳几处、共试探多少权重 × 每个多少次、找到更好值后追加了几遍重跑（`Tune.repeats`）、耗时、权重落盘路径由右栏统计行交代，各算法的两率与权重值看左栏、结果卡与权重框（原来那张卡与统计行、左栏重复）。
- **顶栏（`.stagebar`）只写视图名「算法调优」**（`setStageTitle()`，`#fsub` / `#imgDims` 留空）：样本 / 分类 / 算法个数口径由主图区表头 `#optMeta` 承担，这里不再重复，也避免残留上一个视图的分类名 + 原始截图口径。

### 3.6 执行模式（识别 + 点击）

切换过去即自动截图识别一轮并展示画面与结果，此后页面每 10 秒后台同步一次最新结果；点「立即识别」可手动单轮刷新。「开启自动识别」= 自动循环：每轮「截图识别 → 结果停留 3 秒供查看（可点按钮停止）→ 按下方所选方式执行点击 → 等 3 秒游戏响应」再进下一轮，运行中再次点击即停止。截图复用标注模式的找窗/调窗机制，**只用于识别与展示、不写盘**。

- **识别口径**：把当前帧与 `summary/` 里各分组适用的对照图（15 张基础合成图 = 交集六档 same100/90/80/70/60/50（100% = 全部样本像素一致）与多数/均值/去重均值/8·32 块图族 + 15 张对应的 `-unique` 独有区图，共 30 张；每个分类另含 12 张注意区交集图（以注意点为中心，未设 = 屏幕中心），鼠标点击分类再加 12 张点击区交集图（以点击点为中心），共 42/54 张，需按分类齐全才参与）逐张比对。逐点判据按「代表色来源」分两套：**交集/多数/方框交集类**（交集六档 same100/90/80/70/60/50 / 多数图 major / 8×8·32×32 多数块图 major8·major32 / 注意区交集图 attn8/32-same100/90/80/70/60/50 / 点击区交集图 click8/32-same100/90/80/70/60/50，及各自 -unique（方框交集图无 -unique），共 42 张）颜色是样本真实像素，要求**逐像素完全一致**（R/G/B 三通道差都为 0 才判「匹配」，画面同状态因 resize 逐像素对齐应能精确重现；方框交集图在画面按注意点 / 点击点坐标裁方框后比较）；**均值类**（均值图 avg / 去重均值图 dedup-avg / 8×8·32×32 均值块图 avg8·avg32 / 去重均值块图 dedup-avg8·dedup-avg32，及各自 -unique，共 12 张）颜色是样本平均 / 去重平均色（去重平均 = 每像素 / 块内先把样本出现过的颜色去重再等权平均；真实画面不会恰好等于平均色），用逐通道容差（三通道差都 ≤ `execute.rgb-dist-threshold`（默认 255/3=85）判「匹配」，任一通道 > 它判「不匹配点」）。分类差异度 = 按 A~E 五族加权 (50A+15B+10C+10D+15E)/W——A 全图交集 12 张（same100→50 各带 -unique，权 50）、B 多数族 6 张（max/major8/major32 各带 -unique，权 15）、C 均值族 6 张（avg/avg8/avg32 各带 -unique，权 10）、D 去重均值族 6 张（dedup-avg/8/32 各带 -unique，权 10）、E 方框交集区 24 张（注意区 attn8/32 × 六档 12 张，以注意点为中心每个分类都有；点击区 click8/32 × 六档 12 张，以点击点为中心仅鼠标点击分类有；权 15）：每族先把族内各图「不匹配点占比」等权平均；W = 适用族的权重之和（各分类 42 张五族齐全 W=100，鼠标点击分类 54 张同 W=100；尚未重算的旧产物只有 30 张、无 E，W=85）。权重默认 50/15/10/10/15（当前固定为默认，界面不再提供修改）；各图照常全量参与，产物无任何有效像素的空图（独有区图无独有点 / 基础图公共区全空）没有可判别的点、无法做区分，判完全不匹配、按不匹配占比满值计入；识别以最近似分组为准、**不设识别阈值门槛**（差异度仅作相近程度展示，不再区分「已识别/未识别」）。
- **依赖前提**：目标画面需先在标注模式打好标并生成汇总产物（产物缺失或尺寸不符的分组不参与识别）。
- **执行动作**：识别出「鼠标点击」动作后点「执行动作」，直接按右侧识别结果的坐标发送点击，**不再重新截图识别**（画面已变化请先点「立即识别」刷新结果）：
  - `post`（默认，后台消息）：向目标窗口投递完整点击消息序列，不要求窗口前台/可见、不抢占鼠标（游戏 / 模拟器多忽略合成消息，此时应切 `screen`）；
  - `screen`（前台点击）：`SetForegroundWindow + SetCursorPos + mouse_event` 真实输入（要求窗口可见不被遮挡）。
- 画面区实时帧上用**红白准星**叠加标出识别命中点（点击坐标），右栏展示识别结果与候选分类（差异度由小到大）。

## 六、已知限制 & 待办

- **抓窗限制**：WGC 无法直接抓 `WS_EX_LAYERED` 分层窗口（返回 `E_INVALIDARG`，业界通病）；仅当所有候选窗口都是分层窗时才降级为「显示器捕获 + 窗口矩形裁剪」——此时被遮挡部分会截到遮挡内容、移出屏幕部分被裁掉。
- 目标窗口在**其它虚拟桌面**时抓不到（API 限制）。
- 控制台输出中文乱码多为终端 GBK 显示问题（程序内部均 UTF-8）：先 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 再看日志。
- 多开多个相同目标程序时按标题取「面积最大」，暂无法指定具体实例。
- `capture/` 持续落盘会积累：去重可挡静止/重复画面，长跑建议定期清理（`classify/` 是要保留的样本；`summary/` 可随时删除重算）。
- 识别对轻微光照 / 色偏 / 动态区域敏感，动态画面较多的分类需多采样本覆盖（后续方向：局部 ROI / 特征匹配）。
- 自动点击通过「开启自动识别」进行（每轮留 3 秒可停止的确认窗口）；尚无可配置的策略链（失败重试 / 条件分支等）与执行历史记录。

### B. 截图采集技术（为什么用 WGC）

需求是「**后台** + 抓 **GPU/DX 合成内容** + 多显示器缩放下坐标不偏移」地抓指定窗口——只有微软的 **Windows Graphics Capture**（WGC）满足（`Robot` 要窗口在前台、会截到遮挡层、缩放会偏；`PrintWindow` 对 GPU 分层窗口实测全黑）。因此用 C++/WinRT 写了个单文件采集器 `WindowsCapture.exe`（静态链接，与编译环境无关），Java 用 `ProcessBuilder` 调它：

```
WindowsCapture.exe --hwnd <句柄> --out <输出.bmp> [--timeout-ms 毫秒]
```

退出码分段：`0` 成功；`1xxxx` 参数错误；`2xxxx` 找不到窗口 / 分层 / 抓帧超时等窗口问题；`3xxxx` 内部异常。完整码表见 `native/windowcap/windowcap.cpp` 文件头注释（输出均为 UTF-8）。
