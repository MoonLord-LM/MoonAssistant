# MatchClassifyAct（MCA）

> **Match the pixels, Classify the state, Act accordingly.**
> 匹配像素 → 分类标注 → 执行动作。

Spring Boot 3.2.5 + JDK 17 + JNA 的 Windows **图形程序自动化**工程：对任意 GUI 窗口做「后台截图 → 人工给画面状态打标 → 实时识别当前画面属于哪个状态 → 按定义发送鼠标点击」。默认演示目标是 MuMu 模拟器内的安卓程序，改配置即可自动化任意窗口。

```
截图（窗口内容） → 分类标注（人工，控制台） → 对照图产物（汇总分析）
                                              ↓
                            执行模式：实时画面比对识别 → 鼠标点击
```

---

## 一、快速开始

前置：JDK 17 + Maven；须在**真实桌面会话**运行（无桌面环境抓不到窗口）。

```powershell
mvn -DskipTests package
java -Dfile.encoding=UTF-8 -jar target/MatchClassifyAct-0.0.1-SNAPSHOT.jar
```

- 启动就绪后自动以 Edge/Chrome 应用窗口打开控制台（`http://localhost:8080/annotate`，`--ui.auto-open=false` 可关）；页面会持续探测后端，检测到代码更新后**自动刷新**加载新版。
- 自动采集（截图）**默认不开启**，需在页面右上角点「自动采集」；右上角「完全退出」结束服务并自动关页。
- 日常重启用 `restart.cmd`（停旧进程 → 清 `target\` → 重新打包 → 启动，日志在 `log\`）；`stop&clean.cmd` 只停并清构建输出。
- 数据都在运行目录下，启动自动创建；**可随时整目录拷贝/备份**。

## 二、目录与数据流

| 目录 | 内容 |
|------|------|
| `capture/` | 后台采集的**原始截图**（未标注，`IMG_yyyyMMdd_HHmmss_SSS.png`） |
| `classify/` | 保存标注时图从 capture/ 移入；图旁同名 json **只记归属** `{"state":…}`；`data.json` = **分类定义中心表**（每分类一份动作+坐标） |
| `optimize-weights.json` | 「算法调优」视图应用后的五族权重（存在即覆盖默认 50/15/10/10/15，重启继续生效；删除 = 恢复默认） |
| `summary/<分类标注>/` | **汇总分析产物**：对照图（15 张基础合成图 = 交集六档 same100/90/80/70/60/50（100% = 样本像素完全一致，其余覆盖 >90%/80%/70%/60%/50%）与多数/均值/去重均值/8·32 块图族；每张基础图各带 1 张 `-unique` 独有区图，共 15 张——基础图与独有区图**全部参与识别比对**；每个分类以**注意点**（未设 = 屏幕中心）为中心另含 12 张**注意区交集图** = 1/8、1/32 方框 × 交集六档，鼠标点击分类再以**点击点**为中心另有 12 张**点击区交集图**，同样全部参与比对）+ `info.json`，仅供人工目检 / 执行识别，可随时整目录删除后重算 |
| `summary/_all_/` | 汇总分析列表**固定第一条「全部」**的产物：**12 张** = 交集图 6 张（`same100.png` 100% 档 = classify/ 全部已标注截图的**公共部分**、`same90/80/70/60/50.png` = 每像素取一致张数 >90/80/70/60/50% 的**稳定区**）+ 多数 / 均值 / 去重均值 3 张代表图（`major.png` 多数图、`avg.png` 均值图、`dedup-avg.png` 去重均值图）+ 这 3 族「**与代表图差异最大的一张原图**」（`<kind>-maxdiff.png`，直接复制命中的原图 PNG，不重编码）+ `info.json`（`items` 记 12 张的角标与命中原图名：交集族角标 = 覆盖像素占比，其余族代表图 = 全部原图与该图的平均差异）；不做分类分组、不参与识别比对，仅供整体目检（分类标注若与「全部」同名，目录名自动加 `_cls` 后缀，两者互不影响） |

数据布局例子：

```json
// classify/data.json   —— 分类级统一定义（动作 / 点击点 / 注意点只存这里）
// click 分类：left/top = 点击点（执行时真正点击、必填）；attnLeft/attnTop = 注意点（可选，不写或写 null = 默认屏幕中心）
{ "登录页": { "action": "click", "left": 640, "top": 360, "attnLeft": 500, "attnTop": 300 } }
// 无动作分类：没有点击点，只有注意点（可选，不写或写 null = 默认屏幕中心）
{ "等待中": { "action": "none", "attnLeft": 640, "attnTop": 360 } }
// classify/IMG_xxx.json —— 每张样本只写归属
{ "state": "登录页" }
```

旧版单目录 `captures/`（截图/标注/汇总混排）若存在，启动时自动迁移到上述三分区，之后不再读写。

## 三、控制台使用

左上角「工作模式」下拉在 **标注模式 / 执行模式** 间切换。

### 3.1 标注模式（打样本）

顶栏六段导航：**全部 / 未标注 / 已标注 / 汇总分析 / 特征验证 / 算法调优**。流程：看图 → 填分类标注 → 定匹配动作与点 → 保存并下一张。

- **分类标注** = 画面状态名（登录页 / 主界面 / 弹窗…）。它同时用作汇总产物目录名，故不能含 `\ / : * ? " < > |` 等文件名非法符号（输入时自动剔除）。chip 上的 ✎ 可整体改名（中心表 key 与全部样本归属一并更新，旧产物目录自动清理）。
- **匹配动作** = 无动作 / 鼠标点击，每类各带 **2 个点（双点，编辑面板分三行：分类标注 / 动作 / 点击点·注意点·清除注意点）**：
  - **点击点**（红点）= 执行模式真正点击的位置，仅「鼠标点击」分类有、必填；也是**点击区交集图**的框心。
  - **注意点**（绿点）= **注意区交集图**与识别裁剪的中心，任何分类都可设置；**未设 = 默认屏幕中心**（所有分类一致，不再回退点击点），鼠标点击分类的注意点可与点击点分别设置。
  - 图上用 `点击点 / 注意点` 切换按钮选择当前编辑哪个点，再在图上点一下即可落入该点；只切换编辑目标不算修改，点「清除注意点」才标记为修改（清除后该分类的注意点恢复默认屏幕中心）。
- 每个分类只有一份定义：**首次**打标时确定，之后同分类加样本直接填分类保存即可，坐标自动沿用；在已标注图上改动作 / 点击点 / 注意点 = **重定义该分类**（全组同步，保存前会提示旧定义与新定义的差异）。唯一动作只约束**仍在使用（有样本）**的分类；样本删光后中心表残留的空定义视为全新分类，下次首标会直接重新定义，不会挡你新建。
- 保存后自动带出上次标记并跳到未标注图，快捷键 `↑`/`↓` 切图、`Enter` 保存，可连续快速打标。
- 「已标注」视图里点标签右侧的数字 = 只浏览该分类的已标注图并跳到第一张（再次点击同一数字取消过滤），不会跳去「全部」。
- 左侧列表排序：全部、已标注按时间倒序（最新在上）；未标注按时间正序（最旧在上），从最早的开始逐张往下打标。
- **图片像素 = 窗口坐标**（截图即窗口内容，resize 已逐像素对齐），坐标语义一直沿用到执行点击。

### 3.2 后台截图与去重

- 页面点「自动采集」后按 `capture.interval-ms`（默认 1s）周期后台截图，节拍是 **fixedDelay**：处理完一帧再等这么久取下一帧，绝不叠帧。
- 每帧保存前与历史全部 PNG（capture/ + classify/）全尺寸逐像素比对、统计不一致像素点占比，须与每一张都 > `capture.diff-threshold-percent`（默认 5%）才保存，否则判为重复丢弃；结果以单条轻提示展示在右下角（保存成功 / 与哪张重复）。
- **每次启动**还会在后台自动清理一遍历史重复（自动截图与手动去重任一开启即执行）：按两个启用阈值中较低者（默认 min(5, 0.5) = 0.5%）逐像素比对，只删与保留图不一致像素占比 ≤ 阈值、几乎重复的截图（近似但不相同的画面一律保留），避免误删；画面持续变化产生的新重复仍靠运行期去重挡。清理结果（无论有无删除）在右下角提示一次、并完整进「历史日志」：含参与张数、删除张数、**实际全尺寸比对次数**与**其中最低的不一致像素占比**（= 最接近重复的一对还差多少，未删除时据此判断离阈值有多远；无可比对的同尺寸图时省略该段）与耗时。
- 截图目标尺寸不符 `capture.resize-width × resize-height`（默认 1280×720）时，自动用 `SetWindowPos` 缩放窗口后重截验证，直到 PNG 恰好达标才保存。

### 3.3 汇总分析（生成对照图）

进入「汇总分析」段会自动异步分析每个「样本 ≥1 张且尚未分析」的分组；样本有变也会自动标记待重算。列表**固定第一条「全部」**（不是分类标注、不参与动作过滤与识别比对）= 把 classify/ 全部已标注截图合成**12 张专用产物**：交集图 6 张（100% 档 = **所有图片的公共部分**，只有每一张都完全一致的位置才保留真实颜色、画面里恒定的边框/标题栏之类会浮现出来；90/80/70/60/50% 档 = 每像素取一致张数 >90/80/70/60/50% 的颜色 = **样本间稳定区**）+ 多数 / 均值 / 去重均值 3 张代表图（与该组原图**同尺寸且全不透明**，与分类产物的同名 kind 算法完全一致）+ 这 3 族「**与代表图差异最大的一张原图**」（把全部原图逐个与该族代表图逐像素比对，低 24 位不同的占比最高者胜出，直接复制该原图 PNG 落盘、不重编码）；样本有变时与其它分组同一轮后台重算。产物 = **对照图**（15 张基础合成图 = 交集图分六档：100% 档 = 全部样本像素一致（最严格），其余按覆盖率阈值 >90%/80%/70%/60%/50% 分档，再加多数/均值/去重均值/8·32 块图族；每张基础图各带 1 张对应的 `-unique` 独有区图，共 15 张；每个分类以**注意点**（未设 = 屏幕中心）为中心另有 12 张**注意区交集图** = 1/8、1/32 方框 × 交集六档；鼠标点击分类再以**点击点**为中心另有 12 张**点击区交集图**）+ `info.json`（样本数 / 覆盖率 / 注意点与点击点坐标等），**供人工目检，并作为执行模式实时识别 / 智能分析建议的比对源——只读使用，不自动改动任何标注**（基础图、独有区图、注意区与点击区交集图全部参与识别：每个分类 15 + 15 + 12 = 42 张，鼠标点击分类 15 + 15 + 12 + 12 = 54 张；历史旧产物只有 30/42 张，后台重算后补齐）：

| 产物 | 含义 |
|------|------|
| `same100.png` 交集图（100% 档 = 全部样本一致） | 每像素统计全部样本颜色，仅当**每一张**样本在该像素都同色（一致张数 == 样本数）才保留该真实像素色，任何一张有差别的像素一律透明——交集档里最严格的公共区，只留下所有截图完全恒定的画面；参与识别比对与独有区互比 |
| `same90.png` 交集图（90% 覆盖率档） | 每像素统计样本中主流颜色及其出现占比，覆盖率 >90%（一致张数需超过样本数 × 90%）则取该主流色、不足则透明 = 样本间公共（稳定）区；参与识别比对与独有区互比 |
| `same80.png` / `same70.png` / `same60.png` / `same50.png` 交集图 | 合成方式同上、仅把达标阈值放宽到 >80% / >70% / >60% / >50% 的公共画面，低门槛档保留更多稳定区、与 90% 档互补。**同样参与识别比对**；每档各带 1 张参与比对的 `-unique` 独有区图 |
| `major.png` 多数图 / `avg.png` 均值图 / `dedup-avg.png` 去重均值图 | 每像素取出现最多的颜色 / 全部样本 RGB 平均 / 对样本在该点出现过的颜色**去重后再逐通道等权平均**（同画面重复截再多也只按一个颜色计，抽样不均不再把平均拉偏） |
| `major8.png` `avg8.png` `major32.png` `avg32.png` | 8×8、32×32 块内「多数色 / 均值色」的降采样合成 |
| `dedup-avg8.png` `dedup-avg32.png` | 8×8、32×32 块内「把跨样本出现过的颜色先整块去重、再逐通道等权平均」的降采样合成 |
| `attn8-same100.png` `attn32-same100.png`（注意区交集图 100% 档，**每个分类都生成**：框中心=注意点，未设=屏幕中心） | 以本分类**注意点**为中心、整幅长宽各 1/8 与 1/32 的方框交集小图，框内像素须**全部样本完全一致**才保留该真实色——最严格地只留下「关注位置恒定不变」的画面（框几何、越界透明、无 `-unique` 等规则与下行 90% 档一致），**同样参与识别比对** |
| `attn8-same90.png` `attn32-same90.png`（注意区交集图 90% 档，**每个分类都生成**） | 以本分类**注意点**为中心、整幅长宽各 1/8 与 1/32 的方框交集小图（1280×720 → 160×90 / 40×22），框内逐像素做与交集图 90% 档相同的「覆盖率 >90%」判定，聚焦关注位置（识别裁剪中心）。**框中心固定、不向画幅内收敛**：越出画幅边缘的部分在产物里按透明像素保存，识别时画面按同一坐标裁框、越界处同样填透明——两侧逐点口径一致，越界点不参与统计；无 `-unique` 版、不参与独有区互比 |
| `attn8-same80/70/60/50.png` `attn32-same80/70/60/50.png`（注意区交集图低档，**每个分类都生成**） | 同上、把达标阈值放宽到 >80% / >70% / >60% / >50% 的框内交集小图（框几何、越界透明、无 `-unique` 等规则与 90% 档一致），**同样参与识别比对**；汇总面板按产物是否齐全（`hasAttn` / `hasAttnLow`）展示 |
| `click8-same100.png` `click32-same100.png`（点击区交集图 100% 档，**仅鼠标点击分类生成**：框中心=点击点） | 以本分类**鼠标点击点**为中心、整幅长宽各 1/8 与 1/32 的方框交集小图，框内像素须**全部样本完全一致**才保留该真实色——最严格地只留下「要点位置恒定不变」的画面（框几何、越界透明、无 `-unique` 等规则与下行 90% 档一致），**同样参与识别比对** |
| `click8-same90.png` `click32-same90.png`（点击区交集图 90% 档，**仅鼠标点击分类生成**：框中心=点击点） | 以本分类**鼠标点击点**为中心、整幅长宽各 1/8 与 1/32 的方框交集小图（1280×720 → 160×90 / 40×22），框内逐像素做与交集图 90% 档相同的「覆盖率 >90%」判定，聚焦要点击的位置。**框中心固定、不向画幅内收敛**：越出画幅边缘的部分在产物里按透明像素保存，识别时画面按同一坐标裁框、越界处同样填透明——两侧逐点口径一致，越界点不参与统计；无 `-unique` 版、不参与独有区互比 |
| `click8-same80/70/60/50.png` `click32-same80/70/60/50.png`（点击区交集图低档，**仅鼠标点击分类生成**：框中心=点击点） | 同上、把达标阈值放宽到 >80% / >70% / >60% / >50% 的框内交集小图（框几何、越界透明、无 `-unique` 等规则与 90% 档一致），**同样参与识别比对**；汇总面板按产物是否齐全（`hasClick` / `hasClickLow`）展示 |
| 15 张 `-unique` 独有区图（`same100-unique` / `same90-unique` / `same80-unique` / `same70-unique` / `same60-unique` / `same50-unique` / `major-unique` / `avg-unique` / `dedup-avg-unique` / `major8-unique` / `avg8-unique` / `dedup-avg8-unique` / `major32-unique` / `avg32-unique` / `dedup-avg32-unique`，全部参与识别比对） | 每张对应一张基础图（交集六档 / 多数 / 均值 / 去重均值 / 8·32 块图族）：在**该 kind 基础图**上去掉「**其它分类同 kind 基础图**同位置同色」的像素，剩本分类独有区域，用来拉开相近分类的差距。均为跨分类产物：**要等全部分组的基础图都生成完才开始算**；**该分类适用的对照图必须齐全**（每个分类 15 基础 + 15 -unique + 12 注意区交集图 = 42 张，鼠标点击分类另有 12 张点击区交集图 = 54 张）才参与执行识别——基础图看整幅画面、独有区图只盯本分类独占区、注意区交集图盯关注位置、点击区交集图盯要点击的位置，互补拉开相近分类的差距。接口 kind 与文件名一致（块图无短码，kind 即 `major8/avg8/dedup-avg8/major32/avg32/dedup-avg32`），仅多数图 kind=`max` 对应磁盘名 `major` |

> 「全部」组的 12 张产物（与分类产物**分开**，不参与识别 / 验证 / 调优 / 完备性门禁，卡片由 `/api/app/kinds` 的 `all` 字段单列下发）：
> `same100.png`（交集图 100% 档 / 公共部分，角标 = 公共像素占比）、`same90/80/70/60/50.png`（交集图 90/80/70/60/50% 档 = 每像素取一致张数 >90/80/70/60/50% 的颜色 / 样本间稳定区，角标 = 该档稳定区像素占比）；
> `major.png`（多数图）、`avg.png`（均值图）、`dedup-avg.png`（去重均值图）；
> `major-maxdiff.png`、`avg-maxdiff.png`、`dedup-avg-maxdiff.png`（这 3 族「与代表图差异最大的一张原图」= 命中原图的完整 PNG）。
> 代表图角标：交集图给覆盖像素占比，其余三族给「全部原图与该图的平均差异」；差异最大图角标给差异占比（全图口径），鼠标悬停显示命中原图文件名。
> 交集族不出「差异最大图」：100% 档公共区对所有样本恒一致、差异恒 0 无法区分；第二张直接给 90% 档稳定区图本身。

已分析分组在列表中按**交集 100% 档**（`sameCov.same100` = 全部样本像素完全一致的区域占比，旧产物缺该键时回退用 90% 档覆盖率）**从低到高**排列：该比例越低 = 采到了该状态不同时刻的真实差异（样本更充分），排在前面；越高 = 多为同一画面反复截取（采样不足），排在后面提示补采不同状态的画面。未分析 / 待重算分组排在其后（其中样本多的靠前）。单击任一图放大查看，Esc 还原。

### 3.4 特征验证（第 5 视图，挑算法）

左栏列出**全部 kind**（顺序 = 识别用的 `KIND_ORDER`，不另写清单），每行 = 状态 chip + **只给一个数：C 匹配正确率**（A / B 生成成功率 / 样本数只在主图区的汇总卡与明细表里，列表保持清爽）；主图区给出三个指标的汇总卡与逐分类明细表（分类 / 动作 / A / B 生成成功率 / C 匹配正确率 / 匹配正确个数，个数列形如 `命中 / 样本`，故不再单列样本数）；右栏是说明 + 「开始验证」+ 进度。

- **A（自分类匹配值）** = 每张原图与「自己分类的该算法产物」比对的匹配像素占比（= 100 − 不匹配占比），取全部原图**平均值**：越高说明该分类样本越集中（该算法对本分类稳定）。生成不出有效图的样本按 0 计入。
- **B（生成成功率）** = 能生成有效合成图（产物存在且非全透明空图）的分类数 / 参与分类数：越高说明该算法适用的分类越多。
- **C（匹配正确率）** = 只在「能生成有效图的分类」的样本里，拿去和**全部分类**的该算法产物比对、最佳命中**恰好是自己分类**的比例：越高说明该算法越能把它与别的分类分开。C 告警色：低于 50 红、低于 90 黄。
- **覆盖范围统一**：每种 kind 都拿全部原图 × 全部分类比对，不按动作收窄。某分类没有该 kind 产物、或产物为全透明空图（例如某分类的旧产物尚未重算、缺注意区/点击区交集图、独有区图无独有点）＝无判别点，与「空图」同口径按匹配占比 0 参与 A（它的样本自分类 A 恒为 0）；但它不计入 C 的分母与命中，样本也不会被跳过——明细行的数值列显示「——」并标注「无法生成有效图」，而不是 0%。
- 验证任务在后台单线程 + 并行流跑，结果只存内存不落盘；页面停留该视图时 1 秒轮询进度。跑验证会清空常驻像素缓存腾堆，因此**不要与执行模式的自动识别并行**。

### 3.5 算法调优（第 6 视图，调权重）

识别差异度是五族加权和，权重直接影响识别顺序，本视图用来试 / 自动搜一组更好的权重。

- **主图区**：五族权重滑块（0~120，0 = 整族不参与）+ 「应用权重」/「恢复默认权重 50/15/10/10/15」；下方是「最近一次调优结果」对比卡（默认权重基准 vs 寻优结果：命中自家分类样本数、占比、自家平均差异、最近异类差异、安全边际）与**产物生效范围表**（逐 kind 统计：该产物在多少分类里有有效像素、平均覆盖率）。
- **右栏**：`步长`（寻优步长）与 `随机起点`（起点个数）+「开始调优」+ 进度。调优在后台按 0~120 的权重网格爬山搜索，适应度 = 命中自家分类的样本占比（并列时取安全边际更大的解）。
- 应用后的权重**写运行时并持久化**，「恢复默认权重」会还原 50/15/10/10/15 并删除持久化文件；重启后仍生效。
- 与特征验证同理：调优会重算全量分类的比对矩阵并清像素缓存，**不要与执行模式的自动识别并行**。

### 3.6 执行模式（识别 + 点击）

切换过去即自动截图识别一轮并展示画面与结果，此后页面每 10 秒后台同步一次最新结果；点「立即识别」可手动单轮刷新。「开启自动识别」= 自动循环：每轮「截图识别 → 结果停留 3 秒供查看（可点按钮停止）→ 按下方所选方式执行点击 → 等 3 秒游戏响应」再进下一轮，运行中再次点击即停止。截图复用标注模式的找窗/调窗机制，**只用于识别与展示、不写盘**。

- **识别口径**：把当前帧与 `summary/` 里各分组适用的对照图（15 张基础合成图 = 交集六档 same100/90/80/70/60/50（100% = 全部样本像素一致）与多数/均值/去重均值/8·32 块图族 + 15 张对应的 `-unique` 独有区图，共 30 张；每个分类另含 12 张注意区交集图（以注意点为中心，未设 = 屏幕中心），鼠标点击分类再加 12 张点击区交集图（以点击点为中心），共 42/54 张，需按分类齐全才参与）逐张比对。逐点判据按「代表色来源」分两套：**交集/多数/方框交集类**（交集六档 same100/90/80/70/60/50 / 多数图 major / 8×8·32×32 多数块图 major8·major32 / 注意区交集图 attn8/32-same100/90/80/70/60/50 / 点击区交集图 click8/32-same100/90/80/70/60/50，及各自 -unique（方框交集图无 -unique），共 42 张）颜色是样本真实像素，要求**逐像素完全一致**（R/G/B 三通道差都为 0 才判「匹配」，画面同状态因 resize 逐像素对齐应能精确重现；方框交集图在画面按注意点 / 点击点坐标裁方框后比较）；**均值类**（均值图 avg / 去重均值图 dedup-avg / 8×8·32×32 均值块图 avg8·avg32 / 去重均值块图 dedup-avg8·dedup-avg32，及各自 -unique，共 12 张）颜色是样本平均 / 去重平均色（去重平均 = 每像素 / 块内先把样本出现过的颜色去重再等权平均；真实画面不会恰好等于平均色），用逐通道容差（三通道差都 ≤ `execute.rgb-dist-threshold`（默认 255/3=85）判「匹配」，任一通道 > 它判「不匹配点」）。分类差异度 = 按 A~E 五族加权 (50A+15B+10C+10D+15E)/W——A 全图交集 12 张（same100→50 各带 -unique，权 50）、B 多数族 6 张（max/major8/major32 各带 -unique，权 15）、C 均值族 6 张（avg/avg8/avg32 各带 -unique，权 10）、D 去重均值族 6 张（dedup-avg/8/32 各带 -unique，权 10）、E 方框交集区 24 张（注意区 attn8/32 × 六档 12 张，以注意点为中心每个分类都有；点击区 click8/32 × 六档 12 张，以点击点为中心仅鼠标点击分类有；权 15）：每族先把族内各图「不匹配点占比」等权平均；W = 适用族的权重之和（各分类 42 张五族齐全 W=100，鼠标点击分类 54 张同 W=100；尚未重算的旧产物只有 30 张、无 E，W=85）。权重默认 50/15/10/10/15，可在「算法调优」视图手动改或自动寻优后应用（写运行时并持久化，重启仍生效）；各图照常全量参与，产物无任何有效像素的空图（独有区图无独有点 / 基础图公共区全空）没有可判别的点、无法做区分，判完全不匹配、按不匹配占比满值计入；识别以最近似分组为准、**不设识别阈值门槛**（差异度仅作相近程度展示，不再区分「已识别/未识别」）。
- **依赖前提**：目标画面需先在标注模式打好标并生成汇总产物（产物缺失或尺寸不符的分组不参与识别）。
- **执行动作**：识别出「鼠标点击」动作后点「执行动作」，直接按右侧识别结果的坐标发送点击，**不再重新截图识别**（画面已变化请先点「立即识别」刷新结果）：
  - `post`（默认，后台消息）：向目标窗口投递完整点击消息序列，不要求窗口前台/可见、不抢占鼠标（游戏 / 模拟器多忽略合成消息，此时应切 `screen`）；
  - `screen`（前台点击）：`SetForegroundWindow + SetCursorPos + mouse_event` 真实输入（要求窗口可见不被遮挡）。
- 画面区实时帧上用**红白准星**叠加标出识别命中点（点击坐标），右栏展示识别结果与候选分类（差异度由小到大）。

## 六、已知限制 & 待办

- **抓窗限制**：WGC 无法直接抓 `WS_EX_LAYERED` 分层窗口（返回 `E_INVALIDARG`，业界通病）；仅当所有候选窗口都是分层窗时才降级为「显示器捕获 + 窗口矩形裁剪」——此时被遮挡部分会截到遮挡内容、移出屏幕部分被裁掉。
- 目标窗口在**其它虚拟桌面**时抓不到（API 限制）。
- 控制台输出中文乱码多为终端 GBK 显示问题（程序内部均 UTF-8）：先 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 再看日志。
- 多开多个相同目标程序时按标题取「面积最大」，暂无法指定具体实例。
- `capture/` 持续落盘会积累：去重可挡静止/重复画面，长跑建议定期清理（`classify/` 是要保留的样本；`summary/` 可随时删除重算）。
- 识别对轻微光照 / 色偏 / 动态区域敏感，动态画面较多的分类需多采样本覆盖（后续方向：局部 ROI / 特征匹配）。
- 自动点击通过「开启自动识别」进行（每轮留 3 秒可停止的确认窗口）；尚无可配置的策略链（失败重试 / 条件分支等）与执行历史记录。

### B. 截图采集技术（为什么用 WGC）

需求是「**后台** + 抓 **GPU/DX 合成内容** + 多显示器缩放下坐标不偏移」地抓指定窗口——只有微软的 **Windows Graphics Capture**（WGC）满足（`Robot` 要窗口在前台、会截到遮挡层、缩放会偏；`PrintWindow` 对 GPU 分层窗口实测全黑）。因此用 C++/WinRT 写了个单文件采集器 `WindowsCapture.exe`（静态链接，与编译环境无关），Java 用 `ProcessBuilder` 调它：

```
WindowsCapture.exe --hwnd <句柄> --out <输出.bmp> [--timeout-ms 毫秒]
```

退出码分段：`0` 成功；`1xxxx` 参数错误；`2xxxx` 找不到窗口 / 分层 / 抓帧超时等窗口问题；`3xxxx` 内部异常。完整码表见 `native/windowcap/windowcap.cpp` 文件头注释（输出均为 UTF-8）。
