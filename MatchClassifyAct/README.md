# MatchClassifyAct（MCA）

> **Match the pixels, Classify the state, Act accordingly.** —— 匹配像素 → 分类标注 → 执行动作。

Spring Boot 3.2.5 + JDK 17 + JNA 的 Windows **图形程序自动化**工程：对任意 GUI 窗口做「后台截图 → 人工给画面状态打标 → 实时识别当前画面属于哪个状态 → 按定义发送鼠标点击」。默认演示目标是 MuMu 模拟器内的安卓程序，改配置即可自动化任意窗口。

```
截图（窗口内容） → 分类标注（人工，控制台） → 对照图产物（汇总分析） → 特征验证 → 算法调优（综合最佳算法）
                                                                              ↓
                                                        执行模式：实时画面比对识别 → 鼠标点击
```

---

## 一、快速开始

前置：JDK 17 + Maven；须在**真实桌面会话**运行（无桌面环境抓不到窗口）。

```powershell
mvn -DskipTests package
java -Dfile.encoding=UTF-8 -jar target/MatchClassifyAct-0.0.1-SNAPSHOT.jar
```

- 启动就绪后自动以 Edge/Chrome 应用窗口打开控制台（`http://localhost:8080/annotate`，`--ui.auto-open=false` 可关）；检测到代码更新后页面自动刷新。
- 自动采集（截图）**默认不开启**，需在页面右上角点「自动采集」；右上角「完全退出」结束服务并关页。
- 日常重启用 `restart.cmd`（停旧进程 → 清 `target\` → 重新打包 → 启动，日志在 `log\`）；`stop&clean.cmd` 只停并清构建输出。两个脚本都会**强制以管理员身份运行**（没有权限就用 UAC 重新拉起自己）：`post` / `sendmessage` / `rawinput` / `screen` 都是向目标窗口发消息或注入输入，目标程序（模拟器 / 游戏 / 以管理员运行的程序）权限更高时会被 UIPI 静默丢弃，页面只会显示「点不动」而看不出原因。
- 数据都在运行目录下的 `resource\` 里（五个分区，可整目录拷贝 / 备份），启动自动创建。

## 二、目录与数据流

| 目录 | 内容 |
|------|------|
| `resource/capture/` | 后台采集的**原始截图**（未标注） |
| `resource/classify/` | **已标注样本**：图 + 同名 json（只记归属 `{"state":…}`）+ `data.json` **分类定义中心表**（动作 / 点击点 / 注意点）；另含可随时删除的 `dedup-cache.json`（去重比对结果缓存）与 `opt-weights.json`（当前生效权重） |
| `resource/summary/` | **汇总分析产物**（对照图 + `info.json`）与验证 / 调优结果缓存（`verify.json` / `verify-matrix.json` / `opt-result.json` / `opt-weights.json`），可随时整目录删除后重算 |
| `resource/runtime/` | **运行时算法**（算法调优每次跑完自动重刷）：`algorithm.json` = 综合最佳算法（特征 + 基础分 X + 权重 Y + 各分类动作 / 坐标 / 分辨率），`<分类>/` = 该算法用到的产物。执行模式与「未标注」的智能推荐**只认这里**（删了会提示先完成算法调优） |
| `resource/cache/` | 截图**缩略图缓存**（原图 1/10 抽样小图），供运行期去重预筛；纯加速用，**可随时整目录删除** |

分类定义示例：

```json
// resource/classify/data.json —— 分类级统一定义（动作 / 点击点 / 注意点只存这里）
// click 分类：left/top = 点击点（执行时真正点击、必填）；attnLeft/attnTop = 注意点（可选，不写 = 屏幕中心）
{ "登录页": { "action": "click", "left": 640, "top": 360, "attnLeft": 500, "attnTop": 300 } }
// 无动作分类：没有点击点，只有注意点（可选）
{ "等待中": { "action": "none", "attnLeft": 640, "attnTop": 360 } }
// resource/classify/IMG_xxx.json —— 每张样本只写归属
{ "state": "登录页" }
```

**汇总产物**（`resource/summary/<分类>/`，`info.json` 记样本数 / 覆盖率 / 注意点与点击点坐标）——每个分类 **42 张**（鼠标点击分类 **54 张**），全部参与识别比对：

- 交集图六档 `same100`（全部样本像素完全一致）/ `same90` … `same50`（覆盖率阈值 >90% … >50% 的样本间稳定区）+ 多数 / 均值 / 去重均值 + 8·32 块图族，共 15 张基础图；每张各带 1 张 `-unique` 独有区图（去掉「其它分类同 kind 同位置同色」的像素），共 15 张。
- 以**注意点**（未设 = 屏幕中心）为中心的 12 张**注意区交集图**（`attn8/attn32-same100/90/80/70/60/50`，框 = 整幅长宽 1/8 与 1/32）；鼠标点击分类另有以**点击点**为中心的 12 张**点击区交集图**（`click8/click32-…`）。框中心固定、越界处按透明像素保存，识别时两侧同一坐标裁框。

列表固定第一条「全部」（`resource/summary/_all_/`，**不参与识别 / 验证 / 调优**）：12 张 = 交集六档 + 多数 / 均值 / 去重均值 + 这 3 族「与代表图差异最大的一张原图」，仅供整体目检。

## 三、控制台使用

左上角「工作模式」下拉在 **标注模式 / 执行模式** 间切换。

### 3.1 标注模式（打样本）

顶栏六段导航：**未标注 / 已标注 / 全部 / 汇总分析 / 特征验证 / 算法调优**（页面默认停在「未标注」）。流程：看图 → 填分类标注 → 定匹配动作与点 → 保存并下一张。

- **分类标注** = 画面状态名，同时用作汇总产物目录名，不能含 `\ / : * ? " < > |`（输入时自动剔除）；chip 上的 ✎ 可整体改名（中心表 key、样本归属、旧产物目录一并更新）。
- **匹配动作** = 无动作 / 鼠标点击，每类各带 2 个点：**点击点**（红点）= 执行时真正点击的位置（仅「鼠标点击」分类有、必填，也是点击区交集图的框心）；**注意点**（绿点）= 注意区交集图与识别裁剪的中心（未设 = 屏幕中心）。图上用「点击点 / 注意点」按钮切换编辑目标，再点图落点；只切换不算修改，「清除注意点」才标记为修改。
- 每个分类只有一份定义：首次打标时确定，之后同分类直接沿用；在已标注图上改动作 / 点 = **重定义该分类**（全组同步，保存前提示差异）。样本删光后的空定义视为全新分类，不挡新建。
- 保存后自动带出上次标记并跳到未标注图；快捷键 `↑` / `↓` 切图、`Enter` 保存，可连续快速打标。
- 左侧列表：「全部」「已标注」按时间倒序、「未标注」按时间正序；点标签右侧的数字 = 只浏览该分类的图。
- **图片像素 = 窗口坐标**（截图即窗口内容，resize 已逐像素对齐），坐标语义一直沿用到执行点击。

### 3.2 后台截图与去重

- 点「自动采集」后按 `capture.interval-ms`（默认 1s）周期后台截图，节拍是 **fixedDelay**（处理完一帧再等这么久，绝不叠帧）。
- 保存前与历史全部 PNG（`capture` + `classify`）比对不一致像素点占比，须与每一张都 > `capture.diff-threshold-percent`（默认 5%）才保存，否则判重复丢弃（右下角单条轻提示）。
- **运行期去重 = 缩略图预筛 + 全尺寸精查**：先比 `resource/cache/` 缩略图，差异 < 阈值的一半即直接判重复、不再解码原图；达不到才读全尺寸逐像素比对。于是「判重复」允许被抽样漏掉一点点差异，「判为新画面」始终是全尺寸确认。
- **每次启动**在后台低优先级线程清理一遍历史重复（按两个启用阈值中较低者、全尺寸逐像素，只删几乎重复的），不持锁、不影响其它操作；开始 / 进度 / 结果都提示（进度显示在「未标注」页最下方 tips 行），结果与「实际比对次数 / 复用缓存次数」进历史日志。比对结果按「文件名 + mtime」持久缓存到 `resource/classify/dedup-cache.json`，下次启动直接复用。
- 截图尺寸不符 `capture.resize-width × resize-height`（默认 1280×720）时，自动 `SetWindowPos` 调窗后重截，直到 PNG 恰好达标才保存。

### 3.3 汇总分析（生成对照图）

- 进入本段自动异步分析每个「样本 ≥1 张且尚未分析」的分组；样本有变自动标记待重算。
- 列表按**交集 100% 档覆盖率**（`sameCov.same100`，旧产物缺该键回退 90% 档）**从低到高**排：越低 = 采到了同一状态不同时刻的真实差异（排前，样本更充分）；越高 = 多为同一画面反复截取（排后，提示补采）。从未分析过的分组排在其后。待重算的分组仍按上一次数值排位。
- 右栏：`重新生成全部`（清空 `resource/summary/` 后全量重建）+ `开始分析`（**增量**分析样本已变动的分类）+ 样本库统计行（`样本库：N 张原图 · M 个分类`、`已生成 x/M 组（待生成 · 需重算）`）+ 进度条。
- **没有排队、没有防抖**：任何新请求（样本变动触发的自动重算、点按钮）都当场作废正在跑的旧任务并按最新数据重跑（旧任务标「已被最新一轮取代」提前退出，不算失败）。
- 第 2 轮刷新独有区图期间，列表里**所有**分类行 chip 一律显示「需重算」（独有区图是跨分类产物，此刻谁都还没算完）；跑完才回到「已计算」。
- **进度只显示在各页最下方那条 30px 常驻 tips 行上**（`#tipsBar`，归属由 `TIPS_VIEW` 定死：去重 → 未标注、汇总分析 → 本页、特征验证 / 算法调优各归各页），文本可选中复制；同一页有任务时顶栏对应标签转黄。任务的**开始 / 结束**各由 `toast()` 进一次历史日志，中途不刷屏。

### 3.4 特征验证（挑特征）

左栏列出全部 kind（顺序 = `FrameClassifier.verifyOrder()`），每行两个数：D 匹配正确率 · E 无法区分率；主图区给五个指标的汇总卡与逐分类明细；右栏是说明 + 「开始验证」+ 进度。左栏过滤按钮：`生成成功率100%`（A ≥ 100）与 `匹配正确率80+%`（D ≥ 80）。

- **A 生成成功率** = 能生成有效合成图（产物存在且非全透明空图）的分类数 / 参与分类数。
- **B 自分类平均匹配值** = 有效分类样本「与自家产物」匹配像素占比的平均（越高越稳定）。
- **C 其它分类平均匹配值** = 样本「与其它分类产物」匹配占比的平均（**越低越好**，越低越能区分开）。
- **D 匹配正确率** = 最佳命中**唯一最高**且恰好是自己分类的占比；不能生成有效图、以及分不出高低（最高分被 ≥2 分类并列）的样本都不进分母 → 分母 = 可匹配样本 − 无法区分。D = 100% 的含义是**没错判**、允许存在无法区分样本。低于 50 红、低于 90 黄。
- **E 无法区分率** = **全部可匹配样本**里「无法给出最高值」的占比（≥50 红、≥20 黄）。分母与 D 不同，故 **D + E 不一定等于 100%**。
- 「查看详细」分列各看各的：D 列只列**匹配错误**样本（按被误判到的分类分组、条数多的在前），E 列只列**无法区分**样本（并列的分类 · 最高分 · 自家分）；两个弹窗同一套版式、覆盖整页，标题下用信息 chip 交代上下文。
- 产物无效的分类及其样本不进任何指标统计（明细显示「——」）；每种 kind 都拿全部原图 × 全部分类比对，不按动作收窄。
- **结果完整缓存**到 `resource/summary/verify.json`，逐图比对矩阵缓存到 `resource/summary/verify-matrix.json`（按「大小 + mtime」复用没变过的整表 / 整行，连 PNG 都不解码；**算法调优共用同一份**）。启动后若「已标注 + 汇总产物」一个字都没变即直接恢复上次结果、显示「已计算」；有任何变动立即标记**过期**（chip 琥珀「需重算」+ 弹一次提示），点「开始验证」重算即覆盖。
- 运行中 chip 按本轮进度显示 `计算中…`（正在算它）/ `等待重算`（还没轮到），**运行中不出现「需重算」**。按钮点下即置灰；一旦发现本轮期间数据变动过，按钮**恢复亮绿**（这一轮结果注定作废），点它当场作废旧轮、按最新数据重跑（被作废的一轮不落盘、覆盖不了上次结果）。
- 指纹按「相对各自分区根的路径 + 大小 + mtime」统计，**不含绝对路径**（整个运行目录搬家 / 改名不影响），并排除结果缓存文件与 `*.tmp` 半成品。

### 3.5 算法调优（组合特征成匹配算法）

前置：先在「特征验证」跑完一次且样本 / 产物未变动。本视图报告的两率与 D / E **同口径**（分母都剔除无法区分样本），数值可直接对比。

内置五种算法（算法 1 的选品口径 = **(A − E) × D** 最大，后四个都把「单一最佳」特征作为种子之一带上）：

1. 单一最佳匹配特征（只用它判定）；
2. 单一最佳 + 全部 D = 100% 的特征；3. + 全部 D ≥ 90%；4. + 全部 D ≥ 80%；5. + 全部 D ≥ 70%。
   （2~5 若判定覆盖不全，就对每个缺失分类补入「该分类匹配正确率最高」的特征，直到每类至少有一个特征能判定。）

- **特征表**：基础分 **X = B − C**，权重 **Y ∈ [0,10]**（默认 1、步进 0.001，改 **0** = 该特征不参与本算法）；单一特征算法的 Y 恒为 1、不给编辑框。每行附 A~E 供对照。
- **判定口径**：某分类**匹配度** = Σ「(100 − 不匹配占比) × X × Y」÷ Σ「X × Y」（加权平均，只累加该分类有有效产物的特征）；匹配度**唯一最高**即识别结果；归属分类在该算法参与特征上无有效产物的样本整张跳过、不进分母。
- **打平处理**：某特征在某张样本上最高匹配值被 ≥2 分类并列 → 该样本**整张放弃该特征**（对所有分类一致移除），重新加权后仍并列（或特征被全部放弃）= **无法区分**（既不算命中也不算判错，单独计入「无法区分率」）。
- **改权重 = 立刻锁界面并自动重算**，且请求只带被改动的那个算法（其余算法沿用上次结果，因为同一份矩阵 + 权重没变）。首尾各发一条提示（改了哪个算法的哪个特征、Y 旧值 → 新值；两率变化与用时）。
- **自动调整参数**：复用同一套比对矩阵（换一组权重只跑加权评分，可评估上千次），顺序 = **逐个算法 → 随机组合尝试 → 逐个权重四轮（随机 → 网格 → 最优值微调 → 四舍五入简化）**；每采纳一处立刻把该算法当前全部权重原子写入 `resource/classify/opt-weights.json`（手改该文件刷新即生效，删了回默认全 1）。某个权重采纳过更好值就再追加随机轮重试，避免停在局部最优。单一特征算法不参与调整。
- **结果**：三张并排卡（匹配正确率 / 无法区分率 / 生效特征 N/M = Y > 0 的特征）+ 通栏可折叠的逐分类明细（动作列显示「无动作 / 鼠标点击」）。`刷新算法特征` 与 `自动调整参数` 运行中一律置灰；跑完「刷新算法特征」按**特征验证的值有没有变化**定色（没变 = 当前结果就是按它算的 → 保持灰）。
- **缓存**：结果 + 调参摘要完整写入 `resource/summary/opt-result.json`，「特征选择 + 权重数值」快照写 `resource/summary/opt-weights.json`（供后续功能直接读取）。有效性 = ①已标注 / ②汇总产物指纹 `fp` + ③验证结果新鲜度与算法结构签名 `sig` 三者都对得上 → 启动直接恢复；任一处变动即标记**过期**，但**照常展示上次数据**（卡片标题带「（已过期）」、权重框锁上），重算即覆盖。
- 右栏「!」里是完整口径说明（算法组合 / X 与 Y / 匹配度与打平 / 自动调整参数 / 缓存与过期）；统计行只写最高匹配正确率、综合最佳算法（加粗绿字，执行模式与智能推荐只认它）与调参概况，不重复卡片数值。

### 3.6 执行模式（识别 + 点击）

切过去即自动截图识别一轮并展示画面与结果，此后页面每 0.5 秒轮询一次后端状态（最新画面 + 识别结果 + 循环进度）；点「立即识别」手动单轮刷新。「开启自动识别」= 让**后端**跑整轮循环：「截图识别 → 结果停留 3 秒（期间可停）→ 按下方所选方式执行点击 → 等 3 秒游戏响应」再进下一轮 —— 循环在后端线程（`AutoExecService`），因此**控制台窗口最小化 / 切走 / 关掉都不影响执行**，页面只是观测窗口（倒计时秒数也由后端逐秒下发，页面不做本地倒计时）。截图复用标注模式的找窗 / 调窗机制，**只用于识别与展示、不写盘**。

- **识别口径（只认 `resource/runtime/`）**：识别完全交给算法调优落地的「综合最佳算法」（`algorithm.json` + 该算法用到的产物）。逐特征把当前帧与各分类产物比对（**交集 / 多数 / 方框交集类**要求逐像素完全一致；**均值类**用逐通道容差 `execute.rgb-dist-threshold`）得匹配值，先放弃「最高匹配值被 ≥2 分类并列」的特征，再按 Σ「匹配值 × X × Y」÷ Σ「X × Y」算各分类**匹配度**（差异度 = 100 − 匹配度）。**不设阈值门槛**：匹配度唯一最高即识别结果；最高被并列 = **无法区分**，本轮不动作并给出并列的分类名。没有 `resource/runtime/` 则提示先完成算法调优。
- 画面区用**红白准星**标出识别命中点（点击坐标），右栏展示识别结果与**候选分类（差异度最小的前 7 个）**。
- **执行动作**：识别出「鼠标点击」动作后点按钮发送点击，**点完自动接下一轮**（先等 3 秒游戏响应、状态行有倒计时，再自动识别一次，按钮按新结果恢复；失败不接，画面没变无意义）。
- **五种点击方式**（`execute.click-mode`，控制台「执行模式」页可实时切换、重启后回到配置）：
  - `mumu`（默认，MuMu 模拟器）：把点击交给 `MuMuManager.exe adb -v 0 -c "shell input tap x y"`，不碰鼠标、不动焦点，模拟器在后台 / 被遮挡也能点。**坐标要两步换算**成模拟器内坐标：① 识别点取自窗口截图，先减掉模拟器自身边框 `execute.mumu-click-offset-x/-y`（默认 55 / 60，减成负数按 0）；② 再按「游戏画面 → 模拟器实际分辨率」等比放大（窗口被强制缩小到截图尺寸，模拟器内仍是原始分辨率。**尺寸目前是 `WindowClicker` 里的硬编码常量**，换分辨率要改代码 —— 见待办 2）。
  - `screen`（MouseEvent 前台点击）：抢到前台后用 `SetCursorPos + mouse_event` 真实点击；点击前确认前台焦点已归目标窗口，抢不到就取消本次点击（不冒险乱点），点完也不把前台还回去。要求窗口可见、不被遮挡。
  - `rawinput`（RawInput 前台点击）：`SendInput` 注入系统级真实鼠标输入（移动 → 按下 → 抬起），**必须前台可见** —— 真实鼠标输入只投给「光标下的窗口」，目标点得在屏幕上且该点最上层就是目标窗口。被压住时按「抬窗 → 抢前台 → 临时置顶 → 临时挪到光标处」逐级化解遮挡（开关 `execute.rawinput-auto-expose`），确认目标点已归到该窗口名下才点、点完还原；化解不了就取消本次点击并说明是谁挡着。点击前不主动抢前台，但注入的是真实输入、Windows 会按真实点击语义激活窗口，所以点完它照样会到前台。
  - `post`（PostMessage 后台消息）：`PostMessage` 异步投递完整点击消息序列（滑入移动 → 按下 / 抬起），不要求窗口前台 / 可见、不抢鼠标（游戏 / 模拟器多忽略合成消息）。结果里附一句诊断 —— 用 `GetGUIThreadInfo` 查目标线程的鼠标捕获窗口判断**按下有没有被宿主处理**：捕获 = 本窗口只到「处理」层，宿主收下了 ≠ 会转发给引擎，业务没动就该换真实输入或模拟器自己的 adb 通道。
  - `sendmessage`（PostMessage 后台消息+移动窗口）：`post` 的「同步 + 挪窗对齐」版。先把窗口临时挪到「目标点正好压在当前光标下」（`SetWindowPos` 只挪位置、`SWP_NOZORDER` 不动 z 序也不激活），再用 `SendMessageTimeout`（限时 1 秒）**同步**发同一套消息序列，发完还原位置。专治「不认消息里带的坐标、自己去问 `GetCursorPos()`」的程序；全程只发消息：不碰光标、不抢前台、不受遮挡影响，代价是窗口短暂闪一下。
- 「存入待标注 / 存入分类」点下即全部置灰，成功后才更新状态。

## 六、已知限制 & 待办

已知限制：

- **抓窗**：WGC 无法直接抓 `WS_EX_LAYERED` 分层窗口（`E_INVALIDARG`，业界通病）；仅当所有候选窗口都是分层窗时才降级「显示器捕获 + 窗口矩形裁剪」——此时被遮挡部分会截到遮挡内容、移出屏幕部分被裁掉。目标窗口在**其它虚拟桌面**时抓不到。
- **完全后台做不到**：可后台的 `post` / `sendmessage` 走合成消息，对游戏 / 模拟器（宿主窗口收下了也不转发给引擎）**已定论无解**；`screen` / `rawinput` 是真实输入 → 受 Windows 命中测试约束，「可见」是硬要求。真正后台需输入通道 + 截图通道都后台（ADB `input tap` + `adb exec-out screencap`）。
- 多开多个相同目标程序时按标题取「面积最大」，暂无法指定具体实例。
- `resource/capture/` 会持续积累：去重可挡静止画面，长跑建议定期清理（`classify/` 是要保留的样本，`summary/` 可随时删）。
- 识别对轻微光照 / 色偏 / 动态区域敏感，动态画面多的分类需多采样本覆盖（后续方向：局部 ROI / 特征匹配）。
- 自动点击通过「开启自动识别」进行（后端循环，每轮留 3 秒可停止的窗口）；尚无可配置的策略链（失败重试 / 条件分支）与执行历史记录。循环与页面解耦：页面关闭后循环仍会继续跑，需要停止请点按钮或退出程序（前后台联动见待办 4）。
- 控制台输出中文乱码多为终端 GBK 显示问题（程序内部均 UTF-8）：先 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 再看日志。

待办（2026-09-14 定的方向，尚未开工）：

1. **用户模式**：给普通用户一个「直接能跑」的模式，只暴露必要操作，不展示背后的原理与调优细节（现有标注 / 特征验证 / 算法调优只留给配置方）。
2. **MuMu 模拟器适配**：模拟器真实分辨率（如 2560×1440）应当**自动获取**，而不是像现在这样硬编码在 `WindowClicker` 里；`mumu` 坐标换算第二步的「游戏画面 → 模拟器实际分辨率」要改为从模拟器 / ADB 读实际值。
3. **适配性改造（换资源即换产品）**：首次启动时支持自主配置要处理的**窗口标题**，或直接根据已有的 `resource\` 资源自动适配 —— 同一套程序 + 不同资源包 = 不同用途的产品。
4. **前后台交互锁定（探针机制）**：前台窗口与后台进程互相守望 —— 关闭任一方（关掉前台窗口或杀掉后台进程）都自动把另一个也关掉。

## 附录

### A. REST API 摘要

- 标注：`GET /api/annotate/images`（列图）、`image/{name}`（PNG）、`defs`（分类定义表）、`PUT/DELETE /api/annotate/mark/{name}`、`POST /api/annotate/rename`（分类整体改名）、`POST /api/annotate/delete`（移入系统回收站）。
- 汇总分析：`GET /api/annotate/think/groups`、`POST …/analyze`、`POST …/rebuild`（一键重建）、`GET …/task/{id}`、`GET …/img/{kind}?dir={dirB64}`（`kind` = 产物图名，如 `same100` / `same100-unique` / `max` / `major8` / `attn8-same90` / `click32-same50`，完整清单见 `FrameClassifier.verifyOrder()`；`dir` 为分类目录名 UTF-8 → Base64）。
- 特征验证：`GET /api/verify/status`（全部 kind 的 A/B/C/D/E + 任务进度）、`POST /api/verify/start`、`GET /api/verify/detail?kind=`（分类级明细，含误判 `wrong` 与无法区分 `tied`）。
- 算法调优：`GET /api/optimize/status`（前置新鲜度 + 算法与特征基础分 X + 进度 + 最近结果）、`POST /api/optimize/start`（`{weights:{算法id:[Y…]}, only:[算法id…]}`，`only` 非空 = 只重算这些算法）。
- 截图：`GET /api/capture/status`、`POST /api/capture/pause|resume`。
- 执行：`GET /api/execute/status`（当前点击方式）、`POST …/refresh|act|click-mode|mark|save-to-capture`、`GET …/latest|frame`。
- 其它：`GET /api/app/meta`（版本探针 `codeTs` / 最近截图结果）、`POST /api/system/shutdown`。

### B. 截图采集技术（为什么用 WGC）

需求是「**后台** + 抓 **GPU/DX 合成内容** + 多显示器缩放下坐标不偏移」地抓指定窗口 —— 只有微软的 **Windows Graphics Capture**（WGC）满足（`Robot` 要窗口在前台、会截到遮挡层、缩放会偏；`PrintWindow` 对 GPU 分层窗口实测全黑）。因此用 C++/WinRT 写了个单文件采集器 `WindowsCapture.exe`（静态链接，与编译环境无关），Java 用 `ProcessBuilder` 调它：

```
WindowsCapture.exe --hwnd <句柄> --out <输出.bmp> [--timeout-ms 毫秒]
```

退出码分段：`0` 成功；`1xxxx` 参数错误；`2xxxx` 找不到窗口 / 分层 / 抓帧超时等窗口问题；`3xxxx` 内部异常。完整码表见 `native/windowcap/windowcap.cpp` 文件头注释（输出均为 UTF-8）。
